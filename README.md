## 왜 이렇게 만들었나

나중의 내가 "이건 왜 이렇게 되어 있지" 하고 고치려 들 때를 위한 메모.

- **순공부시간이 동기부여의 핵심이다.** 계획을 몇 개 끝냈는지보다 몇 시간 앉아 있었는지가 더 잘 움직인다. 그래서 달력 칸 색·통계·주간 리뷰가 전부 시간 기준이고, 계획 달성 여부는 칸 안 `1/2` 숫자로만 조용히 표시한다.
- **못 한 날을 비난하지 않는다.** 빈 날은 조용한 회색. 다만 "빈칸이 보여서 자극받는 것"은 원하므로, `이 달의 달성`에서 **내가 도달한 최고 구간보다 위쪽**의 빈 구간만 빗금으로 보여주고 **아래쪽** 빈 구간은 숨긴다(못한 날이 없었다는 뜻이므로 들출 이유가 없다).
- **입력이 무거우면 안 쓴다.** 스톱워치 → 시간 자동 입력, 진도표 → 오늘의 계획 자동 삽입, 채점 대기 → 회차 자동 추론. 손으로 채우는 칸을 계속 줄여왔다.
- **한 가지만 잘한다.** 공부 기록 앱이다. 생활 할 일(치과 예약, 세무 등)은 여기 넣지 않고 미리알림에 둔다. 규칙이 하나로 떨어져야 "이건 어디 적지"를 고민하지 않는다.

## 과목 체계 (바꾸지 말 것)

시험 제도 자체라서 임의로 바꾸면 통계가 전부 틀어진다.

| 상위분류 | 세부 과목 | 시험유형 |
|---|---|---|
| 공법 | 헌법 / 행정법 | 기록형 · 사례형 · 선택형 |
| 민사법 | 민법 / 민사소송법 | 기록형 · 사례형 · 선택형 |
| 형사법 | 형법총론 / 형법각론 / 형사소송법 | 기록형 · 사례형 · 선택형 |
| 상법 | 없음 | 사례형 · 선택형 |
| 환경법 | 없음 | **사례형만** |

- 기록형이 있는 것은 공법·민사법·형사법 셋뿐이고, **기록형은 상위분류로만** 기록한다(세부 과목 선택지가 뜨지 않는다).
- 선택형은 환경법을 제외한 7과목, 사례형은 8과목 전부.
- 세부 과목은 복수 선택 가능하고, 안 고르면 상위분류로만 저장된다.
- 형법을 총론/각론으로 쪼갠 것은 의도적인 것이다.
- 기록형·사례형·선택형 3종은 코드에 고정. 그 밖의 유형(최신판례, 진도별모의고사 등)은 설정에서 추가·삭제한다.

## 화면

### 기록하기

위에서부터 `밀린 진도` → `채점 대기` → `오늘의 계획` → `공부 기록 입력` → `오늘의 기록`.

- **밀린 진도** — 진도표에서 지나갔는데 아직 체크 안 한 항목(최근 60일). "오늘로" 또는 "전부 오늘로"로 당겨온다.
- **채점 대기** — 기록할 때 *채점 결과 기다리는 중*에 체크한 것들. 결과가 나오면 목록에서 득점/만점을 그 자리에 넣으면 대기가 풀린다. 체크하면 진도표에서 회차를 자동으로 채운다(날짜+과목 매칭).
- **오늘의 계획** — 진도표 항목이 날짜가 되면 자동으로 들어온다. 헤더 배지는 그날 요일의 과목을 보여주고, 선택한 날짜를 따라간다(어제 걸 입력하면 어제 요일이 뜬다).
- **공부 기록 입력** — 날짜 / 학습형태(자습·인강) / 시험유형 / 과목 / 세부과목 / 교재·인강 / 진도 범위 / 들은 강 / 시간 / 채점 / 메모. 스톱워치를 멈추면 시간 칸이 자동으로 찬다.

### 달력

월간 히트맵. 칸 색은 **하루 목표 시간 대비 0 / ~25% / ~50% / ~75% / 그 이상 5단계**이고, 100% 달성일은 색이 아니라 **✓ 표식**으로 따로 구분한다. 색을 25%씩 균등하게 나누고 100%만 표식으로 빼면 "낮은 쪽 해상도냐 높은 쪽 해상도냐"의 트레이드오프가 사라진다.
아래에 `이 달의 달성` 비율 띠, 그 아래에 날짜별 상세. 이번 달은 **지나간 날까지만** 계산한다(미래 날짜를 0일로 세지 않는다).

### 통계

주간 리뷰 / 누적 지표(오늘·이번 주·이번 달·연속 기록) / 기간 선택(7·30·90일·전체) / 일별 공부 시간 / 상위분류별·세부과목별·시험유형별·학습형태별 누적 / 상위분류별 정답률 / 정답률 추이(사례·기록형은 득점률, 선택형은 맞은 문항 비율, 각 최근 20건) / 인강 진도율 / 교재별 투입 시간.

세부 과목별 누적은 **복수 선택한 기록의 시간을 나눠서** 계산한다(민법+민사소송법을 같이 고른 60분 기록이면 각 30분).

주간 리뷰에는 **이번 주 손대지 않은 과목**이 뜬다. 목표 대비 %, 공부한 날, 목표 달성일, 과목 균형 막대, 계획 완료 수, 밀린 진도 건수, 하루 평균이 한 장에 들어간다.

### 기록 목록

필터·검색(교재·범위·메모), 수정·삭제, 그리고 `취약 쟁점 모아보기`(기록에 남긴 메모만 모아서 보기).

### 교재 · 인강

상위분류 단위로 등록. 인강은 총 강수를 넣으면 진도율과 남은 강수가 계산된다.

### 설정

시험유형 관리 / D-day / 진도표 / 요일별 계획 / 하루 목표 시간 / 기기 간 동기화 / OneDrive 폴더 자동 저장 / 백업·내보내기 / 초기화.

기본값:

- **D-day** — 변호사시험 2027-01-12, 10월 모의고사 2026-10-16
- **요일별 계획** — 월 공법 / 화 민사(선+사) / 수 형사 / 목 버퍼 / 금 상법 / 토 민사(선+기) / 일 휴식·오후공부
- **하루 목표 시간** — 코드 기본값은 10시간이지만 **설정에서 7시간으로 낮춰 쓰고 있다**(10시간이면 최상위 칸이 거의 안 켜져서 히트맵이 의미를 잃는다)

## 쓰는 법

### 매일

1. 공부 시작할 때 스톱워치 시작 → 끝나면 정지 (시간 칸이 자동으로 찬다)
2. 과목 · 시험유형 · 교재 · 진도 범위를 고르고 저장
3. 사례형처럼 채점이 나중에 나오는 건 **채점 결과 기다리는 중**에 체크해두고, 결과가 나오면 `채점 대기`에서 점수만 넣는다
4. 계획은 체크만. 못 한 건 다음 날 `밀린 진도`에서 당겨온다

선택형은 `맞은 / 푼`, 사례·기록형은 `득점 / 만점` — 둘 다 `분자 / 분모` 형식에 옆에 실시간 % 배지가 뜬다. 만점이 회차마다 달라서 **추이 그래프는 득점률(%)로 비교**한다.

### 새 기기에서 처음 열 때

1. 주소를 연다 (아이폰은 Safari → 공유 → 홈 화면에 추가. 이름 `L공부기록`, 아이콘 ❤️)
2. 설정 → 기기 간 동기화 → GitHub 토큰을 넣고 **연결**
3. 잠깐 기다리면 다른 기기 기록이 내려온다

### 동기화 토큰

GitHub → Settings → Developer settings → Personal access tokens (classic) → **`gist` 권한만** 체크해서 발급. `ghp_`로 시작한다. 기기마다 한 번씩 넣으면 되고, 토큰은 `lawstudy.cfg`에만 있고 동기화 대상이 아니다.

### 진도표 추가

설정 → 진도표에서 과목·이름·시험 구성을 만들고 회차별 날짜와 쟁점을 넣는다. 규칙:

- **n회차 쟁점은 그 회차 날짜에**, **n회차 모의고사는 다음 회차 날짜에** 들어간다 (마지막 회차 모의고사는 다음 평일)
- 모의고사 줄에는 `누적 1~n회`가 붙는다 (출제 범위가 누적이므로)
- 쟁점은 그날 새로 추가되는 범위만 (진도표 칸 그대로)
- **지난 날짜에는 소급 삽입하지 않는다.** 항목 id로 중복을 막고, 한 번 지운 항목은 다시 넣지 않는다

## 데이터

### 저장 위치

| 키 | 내용 | 동기화 |
|---|---|---|
| `lawstudy.v1` | 본 데이터 (아래 `D`) | O |
| `lawstudy.cfg` | GitHub 토큰, gist id, 마지막 동기화 시각 | **X** |
| `lawstudy.timer` | 스톱워치 상태 (running / 누적초 / 시작시각) | X |
| `lawstudy` (IndexedDB) | OneDrive 파일 핸들 (맥 전용) | X |

### 구조

```js
D = {
  version: 4,
  logs: [{
    id, date, type, group, subs[], mode,      // mode: '자습' | '인강'
    material, range, lecFrom, lecTo,          // 인강 들은 강 범위
    minutes,
    qTotal, qCorrect,                         // 선택형: 푼/맞은 문항
    score, scoreMax,                          // 사례·기록형: 득점/만점
    await,                                    // 채점 결과 대기 중 표시
    round,                                    // 진도별 모의고사 회차
    memo, mt                                  // mt = 마지막 수정 시각
  }],
  plans:    { 'YYYY-MM-DD': [{id, text, done, mt, auto}] },
  books:    { '상위분류': [{name, total}] },   // total은 인강에만 사용
  lectures: { '상위분류': [{name, total}] },
  courses: [{ id, group, name, exam, mt, rounds: [{no, date, topic}] }],
  ddays:    [{id, name, date, mt}],
  types:    [{id, name, lectureOnly, mt}],
  settings: { goalMin, week: [{name, key}] },  // week는 월~일 7개
  tomb: { 'log:<id>': ts, 'plan:<date>:<id>': ts, ... },  // 삭제 기록
  updatedAt
}
```

### 동기화 병합 규칙

GitHub 비공개 Gist(`lawstudy-data.json`)에 저장한다. gist id는 파일명으로 자동 탐색하고, 없으면 만든다. 저장 후 2.5초 디바운스로 올리고, 앱 전환에서 돌아올 때도 동기화한다.

두 기기에서 따로 입력해도 사라지지 않도록 `mergeDoc`이 항목 단위로 합친다:

- `logs` / `plans` / `ddays` / `types` / `courses` — **id 기준 union**, `mt`가 큰 쪽이 이긴다
- 삭제는 `tomb`에 남겨서 동기화로 되살아나지 않게 한다. 단 `tomb[key] < mt`면 되살아난다(지운 뒤 다시 만든 경우)
- 교재·인강 — 이름 기준 union, 총 강수는 큰 값
- `settings` — `updatedAt`이 최신인 쪽이 **통째로** 이긴다. ⚠️ 요일표를 두 기기에서 동시에 고치면 한쪽이 덮인다
- 마지막에 `dedupe()`가 이름 중복을 정리한다

### 백업

설정 → 백업·내보내기에서 `.json`(전체 복원용)과 `.csv`(엑셀용)를 받을 수 있다. 큰 작업 전에는 json을 받아두는 게 좋다.

| v4 | 교재·인강 목록을 문자열에서 `{name, total}` 객체로 변경 (인강 총 강수·진도율 도입) |

### 작업 순서

1. **초기 구축** — 과목 체계, 색, 기록 입력, 달력, 통계, 교재·인강, 설정. (개발 대화 앞부분이 잘려 있어 이 구간은 세부가 남아 있지 않다)
2. **아이폰 대응 + 기기 간 동기화 1차** — 모바일 레이아웃, 홈 화면 추가, OneDrive/Microsoft Graph 동기화. 이때 `tomb` 삭제 기록과 `mergeDoc` 항목 단위 병합을 넣었다
3. **아이폰 14 Pro Max 보정** — safe-area를 위쪽만 처리했던 걸 좌우·아래까지 확장. 가로 모드에서 입력창이 확대되던 문제를 `(hover:none) and (pointer:coarse)` 판정으로 해결. 가로에서 통계 4열
4. **동기화를 GitHub Gist로 전환** — `portal.azure.com`에서 "선택한 사용자 계정이 테넌트에 없어…" 오류. 개인 MS 계정은 Azure 테넌트가 없어 앱 등록이 막힌다. GitHub은 이미 쓰고 있으니 토큰만 만들면 되는 구조로 갈아탐
5. **GitHub Pages 배포** — 주소 확정, 파일명을 `index.html`로 두는 규칙이 여기서 생김
6. **중복 항목 버그 수정** — 최신판례와 D-day가 두 개씩 뜸. 기본 항목 id를 기기마다 새로 뽑게 해놔서 맥 것과 아이폰 것이 다른 항목으로 취급됐다. **고정 id**(`dd-bar` 등) + `dedupe()`로 해결
7. **모바일 3종 + 발견한 1종** — 날짜 입력칸이 카드 밖으로 넘침 / 10열 표가 한 글자씩 세로로 쪼개져서 **640px 이하 카드형 전환** / 일별 그래프가 화면 밖으로 나가서 폰에서는 5~7일만 / 스크린샷에서 발견한 "연속 기록" 카드 흰 배경에 흰 글씨
8. **스톱워치 백그라운드 버그** — Live Activities 문의에서 파생. 잠금·앱 전환 시 시간이 멈추고 있었다. 시작 시각을 저장해 **실제 흐른 시간으로 계산**하도록 변경. Live Activities 자체는 웹에서 불가로 결론
9. **세부 과목 색 체계** — 상위분류와 같은 색상, 명도만 분리. 형사법만 3종이라 아래로 넘쳐 유독 어두워지는 문제를 지적받아 다른 과목과 같은 명도대에서 3등분(E안)으로 확정. 교재·인강별 막대에도 상위분류 색 적용. 파일명을 `L공부기록.html`로 변경
10. **요일별 계획 표시** — 기록하기에 오늘 과목 배지(A안), 달력 요일 머리글에 3px 색 띠(나안). 버퍼·휴식은 과목 색과 안 겹치게 무채색, 휴식은 대비가 1.85:1이라 진회색 글씨로 조정
11. **요일별 계획을 설정에서 수정 가능하게** — 이름·색 자유 지정, 기본값 되돌리기. 이 항목만 병합 규칙이 "나중에 바꾼 쪽 전체가 이김"
12. **달력 색 기준 변경** — 계획 완료 여부 → **하루 목표 시간 대비 25% 균등 5단계 + 100% ✓ 표식**(B안). 계획 달성은 색에서 빼고 칸 안 숫자로만
13. **`이 달의 달성` 추가** *(2026-08-09)* — 비율 띠 + 범례. **최고 구간 위쪽 빈 구간만** 빗금, 아래쪽은 숨김. 기록이 없으면 "아직 기록이 없습니다". 이번 달은 지나간 날까지만 계산
14. **진도표 도입** — 송영곤 진도별 모의고사 18회차(8/10~9/2)를 `COURSE_SEED`로 내장. n회차 쟁점은 그 날짜, n회차 모의고사는 다음 회차 날짜. 지난 날짜 소급 삽입 금지, 지운 항목 재삽입 금지. 설정에 진도표 관리 화면
15. **5종 동시 추가** — 모의고사 점수 칸 / 추이 그래프 / **밀린 진도** 카드 / **주간 리뷰** / **취약 쟁점 모아보기**. 모의고사 줄에 `누적 1~n회` 표기
16. **만점 분리** — 100점 고정이던 걸 `득점 / 만점` 두 칸으로. 만점이 회차마다 달라서 **추이 그래프를 득점률(%) 기준**으로 바꾸고 사례형/기록형 필터 추가
17. **입력 형식 통일** — 선택형도 `맞은 / 푼` 두 칸으로 바꿔 사례·기록형과 좌우 대칭. 표 열 이름도 `선택형` · `사례·기록`으로. (이때 선택형 입력 순서가 푼 개수 먼저 → **맞은 개수 먼저**로 바뀜)
18. **정답률 실시간 표시 + 채점 대기 카드** — 입력칸 바로 옆에 % 배지. 사례형 채점이 일주일 뒤에 나오는 상황 때문에 채점 대기 카드를 만듦
19. **채점 대기 오판정 수정** — 유형으로 자동 판정하면 자습 사례형까지 걸린다는 지적. **`await` 플래그 명시** 방식으로 변경하고 유형 제한은 없앰
20. **회차 표시** — 채점 대기가 밀리면 몇 회차인지 구분이 안 되는 문제. `round` 칸을 만들고 체크 시 진도표에서 **자동 추론**(`inferRound`)
21. **인수인계 문서 작성** *(2026-08-11)* — 세션 이전을 대비해 구조·결정 이유·안 하기로 한 것·남은 할 일을 정리

## 안 하기로 한 것

다시 검토하지 않기 위해 이유까지 적어둔다.

- **Live Activities / 다이내믹 아일랜드 스톱워치** — 웹 앱에서는 불가능하다(ActivityKit은 네이티브 전용). 무음 오디오 + MediaSession 우회안은 음악과 공존이 안 돼서 접었다
- **OneDrive 계정 동기화** — 개인 MS 계정의 Azure 테넌트 문제로 포기. GitHub Gist로 대체했다
- **OneDrive 폴더 파일 자동 저장**(File System Access API) — 코드에는 남아 있지만 `file://`에서 권한이 유지되지 않아 사실상 보조 기능이다
- **불렛 저널 / 생활 할 일 inbox** — 앱이 이미 데일리 로그(오늘의 계획), 마이그레이션(밀린 진도), 컬렉션(취약 쟁점)에 해당하는 걸 하고 있어서 두 번째 시스템이 될 뿐이다. 치과 예약·세무 같은 생활 항목은 알림이 필요하고 책상 밖에서 실행되므로 **미리알림**에 두는 게 맞다. 경계는 *공부에 관한 건 앱, 생활에 관한 건 미리알림*
